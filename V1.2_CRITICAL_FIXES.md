## 🎯 **Error Prevention Strategy**

### TypeScript Best Practices
```tsx
// ❌ Bad - Assumes data exists
interface Data {
  value: number;
}

// ✅ Good - Optional properties
interface Data {
  value?: number;
}

// ✅ Good - Safe access
const value = data?.value ?? 0;
```

### Component Patterns
```tsx
// ✅ Always check before rendering
{data?.system && (
  <div>{data.system.cpu_percent}</div>
)}

// ✅ Provide defaults
const cpu = data?.system?.cpu_percent ?? 0;

// ✅ Handle errors
if (error || !data) {
  return <ErrorState onRetry={fetchData} />;
}
```

## 📝 **Lessons Learned**

### 1. Always Make API Data Optional
- Backend responses may be incomplete
- Network errors can occur
- Data structure may change

### 2. Use Optional Chaining
- Prevents "Cannot read property" errors
- Makes code more resilient
- Better user experience

### 3. Provide Fallbacks
- Default values for missing data
- Retry buttons for errors
- Loading states for async operations

### 4. Test Error States
- Missing data
- Network failures
- Incomplete responses
- Edge cases
